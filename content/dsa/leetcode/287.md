## Problem

Given an array of integers `nums` containing `n + 1` integers where each integer is in the range
`[1, n]` inclusive.

There is only one repeated number in `nums`, return this repeated number.

You must solve the problem without modifying the array `nums` and use only constant extra space.

```text
Input: nums = [1,3,4,2,2]
Output: 2

Input: nums = [3,1,3,4,2]
Output: 3

Input: nums = [3,3,3,3,3]
Output: 3
```

Constraints:

- `1 <= n <= 10^5`
- `nums.length == n + 1`
- `1 <= nums[i] <= n`
- All the integers in `nums` appear only once except for precisely one integer which appears two or
  more times

## Approach

The two restrictions kill the easy answers: a hash set is `O(n)` space, and sorting modifies the
array. What is left is to exploit the one thing that makes this problem special, **the values are
valid indices**.

So read the array as a linked list: node `i` points to node `nums[i]`. Every value is in `[1, n]`,
so no arrow ever points at index `0`, which makes `0` a head that nothing links back to. Following
the links from `0` can never return there, and since the walk is infinite in a finite graph it must
eventually repeat the list has a **cycle**.

The node where the cycle starts is a node with **two arrows pointing into it**, and two arrows into
node `v` means two indices `i != j` with `nums[i] == nums[j] == v`. That is the duplicate. So the
answer is the cycle's entrance, and finding a cycle entrance in `O(1)` space is Floyd's algorithm —
the same routine as [142. Linked List Cycle II](/dsa/leetcode/142), run on a list that only exists
implicitly.

```text
nums = [1, 3, 4, 2, 2]

0 -> 1 -> 3 -> 2 -> 4
          ^         |
          +---------+

the tail is 0 -> 1, the cycle is 3 -> 2 -> 4 -> 2 ... entrance 2, which is the duplicate
```

### Floyd's Cycle Detection
- **Phase one** finds *some* node in the cycle. Move `s` one step per iteration and `f` two. Once both
are inside the cycle the gap closes by one each step, so they must land on the same node.
- **Phase two** converts that into the entrance. Reset `s` to the head and advance **both one step at
a time**; they meet again exactly at the cycle's start.

```cpp
class Solution {
public:
    int findDuplicate(vector<int>& nums) {
        int s = 0, f = 0;
        do {
            s = nums[s];
            f = nums[nums[f]];
        } while (s != f);

        s = 0;
        while (s != f) {
            s = nums[s];
            f = nums[f];
        }
        return s;
    }
};
```

- time: `O(n)` — phase one is at most `a + c` iterations, phase two at most `a`
- space: `O(1)` — two indices, and the array is never written to

### Cyclic Sort, and why it doesn't count
```cpp
int findDuplicate(vector<int>& nums) {
    const int n = nums.size();
    int i = 1;
    while (i <= n) {
        int corr = nums[i - 1];
        if (nums[corr - 1] != corr) {
            swap(nums[corr - 1], nums[i - 1]);
        } else {
            i++;
        }
    }
    for (int j = 1; j <= n; j++)
        if (nums[j - 1] != j) return nums[j - 1];
    return -1;
}
```
